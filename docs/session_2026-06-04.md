## 2. EMR_IO 핀 확정 (회로도 Sheet 4, EMERGNCY_I/O)

- **EMR_IO = MCU P10 (Port1.0, 패키지 4번 핀)** 로 확정. 펌웨어가 P1.0을 EMR_IO로 쓰는 것과 일치.
- EMR_IO 네트: **R26 = 220K 풀다운(GND)** + C11 270pF + V1(NC) → R20(STGB1608-102MT 페라이트비드) → CON3(OUT). (이전 검토문서 `schematic_review_v1.md`의 "220k 풀업"은 오기 — 실제 GND 접지 = 풀다운으로 확인.)
- 결론: **active-high 펌웨어 + 220K 풀다운**은 서로 일치(평상시 Low=알람 없음). 폴라리티 문제 없음.

라벨 정정:
- `a96l41x_gpio.c` P0.1 — 잘못된 `// EMR_IO` 라벨 삭제 (P0.1은 실제 OP1N / AN1 배터리 ADC).
- `a96l41x_gpio.c` / `main.c`(hw_initial 중복 블록) P1.0 — `// SENSE PW` → `// EMR_IO`.

## 3. 펌웨어 변경 상세 (모두 main.c, 일부 gpio.c)

### 3-1. EMR_IO 해제 Low 드라이브 제거
- `fire_monitor_step` 화재 해제부 + STEP5 수동테스트 해제부 두 곳에서 `P10 = 0;` 적극 Low 구동 제거(주석 처리). 곧바로 `Port_SetInputpin(PORT1,PIN0,0)`로 입력(High-Z) 전환 → 외부 220K 풀다운이 Low 처리. 다중 유닛이 라인 공유 시 한 유닛이 High 구동 중인 순간의 짧은 Low 드라이브 충돌 방지.

### 3-2. system_count 랩어라운드 (main.c:98)
- `uint16_t` → `uint32_t`. 65536이 42/292/1458의 배수가 아니라 ~3.5시간마다 modulo 위상이 어긋나던 문제 해소(32비트는 ~26년). 선언·대입·모듈로·증가에만 사용 → 동작 변화 없음.

### 3-3. STEP5 SW2 엣지 검출
- 전역 `sw2_prev_pressed` / `sw2_cur_pressed` 추가. STEP5에서 `cur && !prev`일 때만 진입(해제→눌림 엣지). 루프 끝에서 `prev=cur` 갱신. 누른 채로 있어도 테스트/보정이 매 wake 반복되지 않음(long-press=1회).

### 3-4. 저전압 LED_G 0.2초 점멸
- `TIMER2_Int` ISR의 기존 `Bat_Alarm_LED` 블록은 비정적 지역변수(`Gled_mode`/`GLED_CNT`)에 의존해 상태 미유지 = 사실상 미동작 코드였음 → 화재 LED와 동일하게 전역 `Timer2_cnt` 토글 방식으로 교체(`(Timer2_cnt & 0x01)`), 죽은 지역변수 제거.
- 헬퍼 추가: `lowbat_led_blink_start()`(T2_init + Bat_Alarm_LED=1 + Timer2_Start) / `lowbat_led_blink_stop()`(Timer2_Stop + Bat_Alarm_LED=0 + LED_G_OFF).
- 호출부 2곳 래핑: `battery_check()`의 High→Low 진입 즉시 1회 + STEP3 주기 반복. 둘 다 start … `Play_Clip(AUDIO_CLIP_LOWBAT)` … stop.
- 원리: Play_Clip은 블로킹이나 오디오가 Timer1 ISR로 백그라운드 재생 → 전역 인터럽트 ON → Timer2 ISR이 계속 떠 LED_G 깜박. 화재(LED_R)·저전압(LED_G)은 시간상 비중첩.

### 3-5. 화재 알람 SW2 정지(acknowledge) + 버스트 도중 감지
- `play_fire_burst()` 반환형 `void`→`uint8_t`. 화재음 `FIRE_VOICE_REPEAT`(=3, `AUDIO_CLIP_COUNT`와 동일)회 재생 중, **각 클립 사이 0.3초 갭에서 SW2를 20ms 간격 폴링**. 눌리면 `aborted=1`로 남은 클립 멈추고 반환. (외부 연동 relay `with_led=0`은 기존 그대로, 폴링/중단 없음, 0 반환.)
- `fire_monitor_step()` 화재 확정 루프: 매 사이클 P10 High 구동 → `ack = play_fire_burst(1)` → P10 입력 전환 → **`ack`(버스트 중 눌림) 또는 버스트 후 SW2 눌림**이면 `Play_Clip(AUDIO_CLIP_BOOT)` 후 `break`(메인루프 복귀). 아니면 `fire_confirm_avg`로 재감시, 연기 지속 시 루프 반복.

## 4. 알려진 제약 / 주의

1. **버튼 감지 시점**: `Play_Clip`은 블로킹이라 한 클립(~3초) 재생 중에는 SW2를 못 읽고, **클립 사이 0.3초 갭에서만** 감지. 짧게 톡 누르면 놓칠 수 있음 → 클립 끝까지 살짝 누르고 있어야 확실. 클립 재생 중 즉시 중단까지 원하면 오디오 엔진(Play_Clip/Timer1 ISR) 수정 필요(범위 큼, 미적용).
2. **acknowledge 후 재알람**: BOOT음 후 메인루프로 복귀해도 연기가 남아 있으면 다음 STEP1 주기(~8초)에서 다시 화재 감지 → 재알람(영구 묵음 아님). hush 타이머 원하면 별도 작업.
3. **빌드 미검증** — Keil Rebuild 필수.
4. 주석/문서는 한글, **소스(.c)는 ASCII 영문 주석 + CRLF 유지**(원래 ASCII 파일이라 UTF-8 한글 넣으면 Keil(CP949)에서 깨짐).
5. 원소스 보존: 라인 단위 변경은 주석 처리로 남김(`//P10 = 0; ...`). 구조 변경(화재 루프 재작성)은 nested-comment 제약상 인라인 대신 **git 이력에 보존**(되돌리기 가능).
